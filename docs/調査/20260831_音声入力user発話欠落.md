# 音声入力user発話欠落

## Failure

productionの`input_audio`経路で、LLMの応答は返るが`message.received`とsessionのuser rowが
生成されず、assistant側だけが残る事象が発生した。

## Problem

音声入力の同一Triggerについて、利用者の発話とMioの応答を同じsession／Event／Traceで追跡できず、
利用者から見た応答の根拠と会話履歴が欠落した。replyの成功だけでは音声Chatの受付成功を証明できない。

## Cause

`cmd/rencrow`のactive `input_audio` requestは、音声と既存promptをuser messageへ送るだけで、LLM出力を
`user_text`と`reply`へ束縛するCORE system contractおよび`response_format=json_object`を指定していなかった。
LLMがreplyだけを返した場合、`BuildFromLLMFinal`は`UserText`が空でも`ModeLLM` resultを通し、Publisherの
任意user出力条件によりassistant Event／session logだけが発行され得た。

## Lesson

音声をLLMへ渡したこと、replyを受け取ったこと、assistant Eventを保存したことは、音声入力Triggerの
完了証拠ではない。意味上必要なuser transcriptをLLM出力contractで要求し、CORE owner境界で非空を
決定的に検証する。transcriptをreplyや音声chunkからヒューリスティックに推測せず、正規routeを維持する。

## Invariant

- `input_audio`は固定のCORE system contractと`response_format={"type":"json_object"}`で、非空の
  `user_text`（音声転写）と非空の`reply`（既存client／config promptに従う応答）を要求する。
- client／config promptは既存どおり音声と同じuser messageのtext partに置き、system contractへ混ぜない。
- `ModeLLM`の`Result`は非空の`UserText`、`Reply`、`RawFinal`を要求する。欠落時はPublisherより前に
  fail closedし、Event、session log、成功finalを発行しない。
- 成功したuser／assistant Event、session log、受付responseは、同一`ProcessVoiceDirect` Triggerの
  Canonical `TraceID`を保持する。Gateway alias、CHAT route、thinking無効の既存契約は変更しない。

## Enforcement

`postVoiceChatInputAudio`が固定system contractと`llm.ResponseFormatJSONObject`を設定し、既存の
multimodal user messageをそのまま送る。`voiceinput.Result.Validate`が`ModeLLM`の`UserText`を
必須化し、`BuildFromLLMFinal`および`voiceinput.Publisher`からEvent／session logの前に検証する。
missing transcriptは既存bridgeの`VOICE_RESULT_PUBLISH_FAILED`境界へ伝播し、成功eventを送らない。

## Tests

- `TestBuildFromLLMFinal_RejectsUnstructuredFinalWithoutTranscript`で、transcriptなしのplain LLM finalを
  builderが拒否することを確認する。
- `TestPublisherRejectsMissingUserTextBeforeEmittingOrLogging`で、missing transcriptがEvent、session
  log、Job allocationより前に拒否されることを確認する。
- `TestVoiceChatInputAudioBridgeE2E_PostsWAVAndReturnsFinal`で、Gateway requestの
  `response_format=json_object`、固定system contract、既存client promptのuser text part保持、
  `input_audio`構造、既存samplingおよびthinking無効を確認する。
- `go test ./internal/application/voiceinput`、`go test ./internal/application/orchestrator -run 'VoiceDirect'`、
  `go test ./cmd/rencrow -run 'VoiceChat(InputAudio|WebSocket|Bridge|Enabled|Infer|Register|Annotate)'`を実行する。
