# RenCrow_Harness設計v0.2.2のCORE正本反映台帳

## 概要

RenCrow_Harness設計v0.2.2（設計パッケージzipのSHA-256は`802a00297bf8c0ed01e4c0ce254f7663aadbf30da7163305e88625969f098c53`）の決定のうち、
COREが所有する共有契約と連携境界を、CORE正本のdocsへ反映した。反映した文書は11本である。
RenCrow_Harnessは採用済み設計・未実装であり、`RenCrow_Harness` repositoryは未作成、EcoSystemへ未登録、runtime試験97件は全件`not_run`のままである。
反映した各節は「Status: 採用済み設計・未実装（RenCrow_Harness設計v0.2.2、2026-10-07）」を明記し、実装済みと誤読されない書き方にしている。

## 発生条件

- 読取基準のCORE HEADは`82472307`で、設計パッケージが参照するpinと同一である。
- 設計v0.2.2が2026-10-07に確定し、CORE正本（`docs/README.md`が兄弟moduleとの境界の唯一の正本と定める文書群）への反映工程（ロードマップのWP01のCORE分）に入った。
- 作業開始時点の既存の未追跡file2件（`data/orchard.sqlite3`と`docs/調査/20261006_200703_RenCrow_Harness仕様v0.1_評価.md`）には触れていない。

## 手順

1. 設計パッケージの決定（AD-01〜AD-17、Q01〜Q17）と付属契約から、COREが所有する事実を抽出した。
2. 一つの事実は一か所だけに詳述し、他文書はlinkで参照する割当表に従って、文書別の担当で追記した。
   境界の構造は04、利用者から見た機能は02、Shiroの選択規則は03、設定は05、Public APIとの境界は06、由来と安全は07、工程は08、観測は10、IDの発行者はIdentity正本が正本である。
3. 既存の契約文は削除・弱体化せず、追記と、Harness導入で意味が変わる箇所の最小修正だけを行った。
   既存の`codex.run`、Kuro／Heavy Codex Exec、IdleChat CodexExe、ShiroのCodexWorkPathとSubagent経路は「未選択routeは現行どおり」として維持している。
4. 04内でprincipalと既定originの値を書いていた箇所を、05の設定項目（正本）へのlinkに置き換え、値の重複をなくした。
5. 全体検証（禁止語、局所path、相対linkとanchor、空白、関連Go test）を実行した。結果は別途の作業報告に残す。

## 結論

COREが所有する共有契約と連携境界は、上記の11文書へ反映済みである。反映は「採用済み設計・未実装」の契約であり、実装、production wiring、配備、試験の完了を意味しない。
状態を「実装済み」へ変えるのは、実装、production wiring、test、配備の証拠が揃った時点である（08のロードマップ節に記載）。

### 実装時に確定して追記する事項

- 05: Harness委譲設定のconfig key配置とstruct名、`limits`の具体値。
- 10: ログのfield名とevent名（`### RenCrow_Harness委譲の相関`へ追記する）。
- 子processのstderr保存先（WP08で確定し、10 `### RenCrow_Harness`へ追記する）。
- 06: 委譲結果のViewer／API projectionのfield。

### 範囲外として未実施

- RenCrow_LLMのcaller、Public API、正規化、計数の正本更新。
- RenCrow_EcoSystemへのmodule登録。
- `RenCrow_Harness` repositoryの作成。
- コード、config、testの変更。
