# X Bookmark参照先未表示・未取得 調査報告

## 結論

原因は、CORE Viewerの読み取りprojectionが`meta.references`を件数に折り畳んでいたことと、
旧Windows Vault移行recordの外部URLが`legacy_vault_reference`としてURLだけを保持し、
外部page本文の取得工程を通っていなかったことの2点でした。

## 証拠

- production DBのX Bookmarkは6,125 record、referenceは21,545件でした。
- reference内訳は`external_url=18,378`、`x_post=3,167`で、調査時のexternal referenceは全件
  `legacy_vault_reference`、`body_text`保持0件でした。
- 旧Viewer APIは`reference_count`だけを返し、referenceのURL、title、description、本文、
  取得状態をresponseへ含めていませんでした。

## 反例検証で見つかった追加不具合

外部page内の最初の`article`要素を無条件で本文とすると、本文のないpageで
関連記事・おすすめcardを本文と誤認しました。この結果はCOREへ取り込まず、fixtureを
回帰test化しました。抽出はArticle系JSON-LDの`articleBody`、明示的な本文selector、
十分な長さの`main`を優先し、汎用`article`は200文字以上の最長候補に限定しました。
本文を特定できない場合はtitleとdescriptionを保持し、`fetch_failed/empty_body`とします。

## 対応

- Debug Viewerの左端ナビゲーションへ`X Bookmark`を常設しました。
- Viewer APIへ安全なreference DTOを追加し、card内でURL、解決後URL、状態、title、
  description、本文、文字数、切詰め、取得時刻、失敗理由を表示しました。
- X Bookmark検索対象へreferenceのURL、title、description、本文、X投稿文を追加しました。
- `rencrow-x-bookmarks-enrich-links`をRenCrow_Toolsへ追加し、旧recordの未取得URLを
  入力非破壊、上限付き、再開可能なJSONL artifactへ補完できるようにしました。
- npm linkのシンボリックリンク経由でCLIが無処理終了するentrypoint判定不具合も
  回帰testを追加して修正しました。

## 検証

- CORE対象Go test、Viewer JavaScript構文検査、ToolsのX Bookmark回帰testは成功しました。
- 実URLのClaude Platform Docsからtitle、description、9,251文字の本文を取得しました。
- 初回25 URL batchは13 URLの本文取得、12 URLの理由付き失敗、4 record更新でした。
- CORE取込後もX Bookmarkは6,125件、pendingは6,125件で、自動promotionは発生していません。
- Playwright Firefoxで左ナビリンク、専用画面への遷移、検索、参照先のtitle・description・
  本文展開を確認しました。390×844の横h overflowはなく、専用画面のconsole errorは0件でした。

## 残件

初回batch後も未処理unique URLは16,073件あります。全件のバックフィルは
長時間の外部通信を伴うため、`enriched_core.jsonl`を次回入力にして上限付きbatchを
継続します。新規browser収集分は収集時に同じ外部本文取得を実行します。
