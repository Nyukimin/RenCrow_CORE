# CODEルーティングE2E期待値不整合

## 調査概要

- 調査日時: 2026-07-26 17:52 JST
- 対象: `test/e2e/routing_test.go`
- 事象: 全E2Eタグ実行で、期待route `CODE` に対して実際のrouteが `CODE2` となり1件失敗した

## 仮説と確認結果

1. 実装が誤って汎用`CODE`を`CODE2`へfallbackしている
   - 反証。`DefaultCodeExecutor`は汎用`CODE`をCoder1専用として扱い、Coder1不在時は明示的な`CODE2`〜`CODE4`を要求する。
2. 分類器が実装要求を`CODE2`へ分類する現行契約と、E2Eの期待値がずれている
   - 確認。失敗したE2Eは自然言語の実装要求に対して旧`CODE`期待を固定していた。
3. Coder1不在時にCoder2へ暗黙fallbackする旧挙動が現在も必要である
   - 反証。正本仕様は別character、別Role、別providerへの無言fallbackを禁止している。

## 根本原因

E2Eが、削除済みの「Coder1不在時にCoder2へ暗黙fallbackする」契約を保持していた。
現行の実装と正本仕様ではCoder1〜4を明示routeで選択し、別Coderへ暗黙fallbackしない。
そのため、分類器が実装要求を`CODE2`へ分類した現行結果は正常で、E2Eの期待値が古かった。

## 修正

- 自然言語の実装要求を期待route`CODE2`へ修正し、ルール辞書による分類からCoder2の実応答までのカバレッジを維持した。
- Coder1の到達E2Eは明示入力`/code1`と期待route`CODE1`へ揃え、自然言語の実装分類とCoder1の明示選択を混同しないようにした。
- productionのルーティング実装は変更していない。

自然言語分類の期待routeはルール辞書の現行契約と一致させる。
