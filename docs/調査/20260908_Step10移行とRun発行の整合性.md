# Step10移行とRun発行の整合性

正本は[Identity Canonical](../architecture/identity/IDENTITY_CANONICAL.md)のStep10。
本書は今回の設計判断と失敗知識を記録する。実行結果の正本は
`Tmp/test-runtime/_identity-remediation/step10-migration-cas/full/receipt.json`であり、
source hashが一致するpassed receiptだけをsource検証として採用する。

## Failure / Problem

checkpointからの再開でTaskIDだけを指定すると、並行した後継発行や別の明示rerunを
自分の再開と混同し得る。また、生成前のRun照合だけでは生成中のRun差替えを排除できない。
個別storeの変換成功だけでは、Task、Run、Event、artifactの参照整合は証明できない。

## Cause / Lesson

事前読取と発行が異なるtransactionに分かれ、発行済みRunに保存済みcheckpointとの
因果を照合する内容証拠がなかった。検証単位も個別storeに分かれていた。
共有providerの一時差替えはmutexで代入を守っても、並行する別Runへの設定漏出を防げない。

## Invariant / Enforcement

- Task ownerが期待する直前Run、actual assignee、開始理由、保存済みcheckpointのSHA-256を
  同じtransactionで照合する。競合は更新ゼロで拒否し、発行時digestは以後変更しない。
- 後継の採用でも同じdigestを照合する。timestampだけで因果を推定しない。
- 同期の外部生成leafはTask ownerの読取transaction内で実行する。checkpoint保存や
  Task完了をcallbackへ入れず、call-local providerを使い、共有設定を差し替えない。
- 移行はCOREの一時owner CLIで、明示した全13role、入力hash、出力hash、件数を照合する。
  dry-runとapplyが同じ結果である場合だけfresh cohortを公開し、完全一致時だけnoopとする。
- 未知schema、不明な帰属、orphan、曖昧参照、source driftは推測せず拒否する。
  RunningをInterruptedにする場合はSuperAgentの詳細projectionも同じ終了時刻へ揃える。
- 旧source名を扱う移行packageは一時CLIからだけimportできることをarchitecture testで強制する。
  runtimeの旧契約禁止を移行コードにも一律適用すると変換に必要な由来まで拒否するため、
  offline境界のimport検査とruntimeのtoken検査を対にする。この検査を全体回帰の前に実行し、
  個別変換試験だけを先に積み上げて境界違反の発見を遅らせない。

## Tests

`taskmanager/run_checkpoint_test.go`は同時発行の一意性、古い期待Run、Actor不一致、空digest、
保存失敗rollback、外部生成中の差替え排他を検証する。
`idlechat/generation_run_checkpoint_test.go`と既存回復試験は保存済みintent、digest照合、
後継保存失敗、生成失敗の境界を検証する。
`persistence/runmigration`は全roleのfixture、owner reload、本文保持、hash一致、noop、
不正参照、旧payload参照、未照合checkpoint、filesystem aliasとdriftを検証する。

## 運用上の未確認境界

本番writer停止、snapshot全体の網羅性、実際の履歴schemaへの適合、復旧artifact、cutover、
配備後の実Agent／Viewer／再起動はsource試験で代用しない。
現行CLIは非終端queue、後継未照合checkpoint、型別変換のないEvent内旧実行参照、
owner必須metadata欠落を拒否する。検査を弱めず、source ownerの証拠と変換契約を確定する。
同期leaf中は同じTask storeの更新も待つため、取消・期限を守る呼出先を使う。
process終了後に遠隔側へ残った効果の停止やexactly-onceは、この排他の保証範囲に含まれない。
