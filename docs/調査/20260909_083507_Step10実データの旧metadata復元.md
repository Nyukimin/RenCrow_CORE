# Step10実データの旧metadata復元

正本は[Identity Canonical](../architecture/identity/IDENTITY_CANONICAL.md)のStep10配備契約。
対象ownerはCOREのoffline runmigrationであり、runtimeのActor登録や実行経路は変更しない。

## Failure / Problem

fixtureだけの移行試験では、実データの欠落metadataを検出できていなかった。
旧子実行74件にActor field、再開情報288件にCheckpointID、queue4件にRun参照がない。
別途、旧再開不可状態3件に終了日時、子実行74件とContextPack315件にsecondary Run indexがない。
旧Dialogue 2,393件とStory 2件は最初の要修復から後にreadyとなるが、旧変換は最初の行をRun状態にしていた。

## Cause / Lesson

旧producerと過去の移行が保持した情報の場所が異なっていた。月別archive帰属を子実行へ
広げる仮説は誤りであり、旧IDの実Agent名と保存日時の一致が帰属の根拠になる。
~/.rencrow/backupsだけの検索では不足し、~/.rencrow/backup/recoveryの移行前後artifactを
参照する必要がある。queueはgoalや時刻の類似ではなく、元IDの写像と同じTraceで結ぶ。

## Invariant / Enforcement

- 子Actorは旧producer 1c36fe0のID形式とCreatedAtのUnixNanoを照合する。74件はShiroと一致。
- checkpointは保存内容を保持し、既存queueとの一致を要求する。未知・矛盾・別Task共有を拒否する。
  同一Taskの後継RunへのCheckpointID継承は正規resumeとして保持する。
- 旧recovery 43096d9の固定再開不可状態だけを移行時点でInterruptedへ閉じる。
  過去の終了時刻を復元したとは扱わず、元snapshotを保持する。
- 空のsecondary indexだけを既存payloadから再構築し、値のある不一致は拒否する。
- queue参照はStep16の移行前後7件のID一致とEvent Traceから検証する。
- 旧IdleChat generationは全revisionを読み、最後の生成revisionでRun状態を確定する。
  同一revisionの再保存・再生更新は終了時刻を動かさず、Actor変更、revision逆行、同一revisionの状態矛盾を拒否する。
  履歴行は全件保持し、既存の正規Runを投影から上書きしない。
- 全変換は既存CLIのhash-bound入力、fresh出力、dry-run/apply/noop、owner reloadの境界内に置く。

## Tests

runmigrationのcheckpoint_test、child_actor_test、recovery_state_test、reference_index_test、
queue_reference_testが、欠落時の失敗、復元、曖昧性拒否、owner読取を検証する。
実行結果の正本はTmp/test-runtime/_identity-remediation/legacy-metadata-conversion配下の
固定planとreceipt。Fullの成功はsource hash一致を要求し、配備済みとは扱わない。

## 未確認境界

診断コピーは13role、writer稼働中のcaptureであり、本番移行には使用しない。
Storyの旧生成Actor、実データ全体でのowner再読取、旧Event payloadの型別変換、停止後snapshot、
cutover、実Agent／Viewer／再起動の終端証拠は別途閉じる必要がある。

## CLI / LLM / Boundary

実装後の変換・照合はすべてCLIで決定的に実行する。runtime LLMの追加はない。
旧producerの意味の解釈と未記録Actorの確認がLLM／利用者の知識に依存する残余であり、
未確定な内容をCLIへ推測させない。保存、公開、配備はCOREのBoundaryで検証する。
