## 概要

人物関連の照会・手動収集・identity・summary能力は本番でreadyだが、評価済みD1人物をカテゴリ収集へ順番に投入するproduction Workerが存在しない。また収集適格者は人物自身のpositive評価だけに限定され、positive映画から直接到達する人物を含めていない。

## 調査経緯

### 仮説1: 自動カテゴリ収集Workerがない
- **根拠**: production logにはlookup、collect Tool、identity Worker、summary Workerのreadyだけが記録される。
- **検証結果**: 確認
- **証拠**:
  - runtime dependencyはidentity Workerとsummary Workerだけをstartする。
  - `person_related_catalog.collect`はWorker専用Toolとして手動要求時だけ実行される。
- **チェックリスト結果**:
  - [x] 確証バイアス: collect Tool自体はreadyという反証を確認した。
  - [x] 頻度制約: 自動投入がないためpositive評価後に毎回不足する。
  - [x] ライフサイクル: identityのenqueue/claim/completeとsummaryのenqueue/claim/completeを確認したがcategory collectionのstart/stop対はない。
  - [x] 既存知見: 関連する過去調査の棄却記録はない。

### 仮説2: 映画D0から人物D1への収集適格性が欠ける
- **根拠**: `EligiblePeople`と`EligiblePersonByID`が人物assessmentの`known | like`だけを見る。
- **検証結果**: 確認
- **証拠**:
  - positive映画assessmentと`movie_people`の直接edgeを使う選択条件がない。
  - D1カード投影は直接edgeを表示できるが、collection eligibilityとは接続されていない。
- **チェックリスト結果**:
  - [x] 確証バイアス: 現行productionには明示positive人物が684件存在する反証を確認したが、それは映画D0からの恒久的な導出契約ではない。
  - [x] 頻度制約: 新しい映画をseenにした場合に同じ不足が再現する。
  - [x] ライフサイクル: assessment保存後のD1 projectionとcollection経路を双方確認した。
  - [x] 既存知見: D1はdirect relationだけという既存仕様と整合する。

## 根本原因

- **原因**: D1カード投影、identity解決、手動収集Toolは実装されたが、positive映画から人物を選び、カテゴリ収集を継続実行するorchestrationが未接続だった。
- **メカニズム**: assessmentはmovie catalogへ保存されるだけで、person-related collectorへ仕事が供給されない。
- **影響範囲**: ドラマ、受賞歴、音楽、アニメ、小説、漫画の人物関連カテゴリ。

## 修正案

1. positive人物に加え、positive映画からvalidated direct creditで到達する人物を収集適格者にする。
2. durable cursorを持つbounded collection Workerを追加し、既存planner/receipt/importを一件ずつ実行する。
3. D1から先を再展開せず、既存のsource policy、rights、TTL、rate limitを維持する。

## 関連ソースファイル

- `internal/application/personrelatedcatalog/catalog.go` - 現行の収集適格者選択
- `cmd/rencrow/runtime_person_related_catalog_collect.go` - 手動収集実行境界
- `cmd/rencrow/runtime_dependencies.go` - production background Worker起動
- `internal/application/moviecatalog/card_projection.go` - D0/D1直接関係投影

## 教訓（将来の調査への知見）

- ToolがSnapshotに存在することと、継続的な仕事がToolへ供給されることは別の完成条件である。
- D1表示とD1収集は同じroot/edge契約を共有し、別々の適格性定義を持たせない。
