# システム概要

RenCrow_CORE は、会話型インターフェースと作業実行を、安全な複数エージェント構成で統合する orchestration runtime です。

## 目的

- 人格を保った自然な対話と、明示的な作業依頼を同じ入口で扱う。
- 会話、判断、提案、実行、policy判定の責任者を分離する。
- 会話履歴と Knowledge を provenance 付きで Recall する。
- 長時間の作業を Workstream、Scheduler、Heartbeat で継続する。
- 実行状態、失敗、degraded状態をDebug Viewerから観測し、外部利用者にはRenCrow_PORTALで許可した状態だけを公開する。

## CORE が所有する範囲

- RenCrow_ASSISTANT、RenCrow_PORTAL、Debug Viewer、LINE、Slack、Discord、Telegramなどの入力契約
- Mio による通常メッセージの route decision と明示 command の優先
- Agent、Advisor、Tool の契約と責務境界
- Persona、会話履歴、RecallPack、Knowledge Relation、trace
- side effect 前の同期policy判定と監査記録
- Workstream、Backlog、Scheduler、Heartbeat、Economic Objective
- Viewer REST/SSE と外部 module の状態 projection

| モジュール | 所有する実装本体 |

| RenCrow_Irodori_TTS | Irodori engine、model、reference音声、SEED、推論parameterを持つ演算target |
| RenCrow_Vision | COREから画像・動画を受け、Wildで解析し、正規化した結果をCOREへ返す認識interface |

## Snapshot repository

RenCrow_Workspaceは外部runtime moduleやserviceではありません。
実行時の正本である`~/.rencrow/workspace`からportableな非secret要素だけを保存する
snapshot repositoryであり、backup／復旧に利用します。COREは実行時に
RenCrow_Workspaceのcheckoutへ接続せず、secret、database、logなどのruntime固有状態を
snapshotへ含めません。

CORE は意味route、Agent、AgentからExecution Roleへの割当、Persona、Memory、Recall、
Tool policy、外部providerへ入力を送信してよいかの判断を所有します。LLM実行時は
RenCrow_LLM Gatewayの単一URLと論理execution aliasだけを使い、物理Model、Backend URL、
port、command、Host Nodeを選択しません。外部 module が未起動でも CORE の実装欠落とは
限らず、利用時には明示的な unavailable/degraded として扱います。

Mio、Shiro、Midori、Kuroは同じAgent管理単位である。利用する推論実体がローカルModel、
外部API、Codex等のAgent Runtimeのいずれであっても、Agentの人格、会話、Memory、
実行policy境界はCOREに残る。Agentと推論targetの間にはChat、ChatWorker、Worker、Wild、
HeavyのExecution Roleを置く。特にKuroはCodexそのものではなく、Heavy Roleの現在の
targetとしてCodex subscription runtimeを利用するAgentである。

ASSISTANTの生活Routine schedulerとCOREのWorkstream、Scheduler、Heartbeatは別責務です。目覚まし、予定、天気、交通、ニュースの定型配信はASSISTANTが所有し、複数工程、生成、継続監視、policy判定を伴うside effectはCORE Taskへ移譲します。

PORTAL、CMD、ASSISTANTはCOREの周囲に置く兄弟moduleです。Chat、IdleChat、recipient、
event、session、audio、Task、errorの意味はCORE Public APIを基準に揃えますが、
PORTALはWeb、CMDはterminal、ASSISTANTはproactive triggerとDevice deliveryを固有差と
します。ASSISTANTだけはpersonal／family／Routine／delivery状態を所有する常駐serviceで、
COREはASSISTANTを必須依存にしません。
