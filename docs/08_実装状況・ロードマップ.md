## Kuro / Heavy Codex Execの確定済みside effect境界

KuroをMio、Shiro、Midoriと同格のAgentとし、Persona、Memory、会話SessionをCOREに
保持する設計を採用しました。HeavyはKuroと推論Targetの間に置くExecution Roleとして
維持します。CORE `main`のproduction wiringは、Kuroの通常応答を
`Heavy provider -> RenCrow_LLM kuro alias -> kuro_codex -> codex_cli`へ接続し、
`codex exec --json --sandbox danger-full-access --cd <CORE workspace> --ephemeral`を実行します。
このproduction wiringとtestを実装済み判定の根拠とし、日時付き実requestやdeploymentの
稼働証跡は`docs/調査/`へ分離します。この経路自体は未実装課題ではありません。

通常Kuro推論は`danger-full-access`を正式採用します。RenCrow_LLMはKuro／Heavy bindingの
Role profileを`agent_runtime`かつ`danger-full-access`に固定し、target sandboxにも
`danger-full-access`を要求します。`none`／`read-only`への設定変更はvalidation errorです。
COREの`codex.run` Toolは別経路で、引き続き`danger-full-access`を拒否し、
`read-only`または`workspace-write`だけを受理します。
RenCrow LLM Runtime導入やCodex thread継続は推論側の変更であり、KuroのAgent identity、
HeavyのRole identity、COREのMemory、Tool実行policyを移動しません。

## Deployment またはライブ検証に依存するもの

外部 LLM/STT/TTS/Vision/Image/GAMES runtime の起動、各演算backend、実ブラウザの
responsive表示、実音声再生は環境依存です。コード実装済みでも、各deploymentではhealth、
実request、実表示・再生を別々に検証してください。標準installerのGo配布と、外部computeの
deployment readinessは別の受入条件として扱います。

GPU、model、port、常駐方式、ある時点の起動・停止状態は各deploymentの観測情報であり、
この文書の実装済み判定へ固定しません。必要な時点で各moduleのhealth、実request、実表示・再生を
再確認し、日時付き証跡は`docs/調査/`へ保存します。
